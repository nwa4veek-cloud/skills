# SEO

Reusable SEO instructions for coding agents building websites, apps, landing pages, content hubs, marketplaces, program pages, portfolios, and public product pages.

Use this with the Universal App Building Instructions. SEO should be built into the page structure, content, metadata, performance, accessibility, and publishing workflow rather than added as a thin final layer.

---

## Core SEO Goal

Build pages that are:

- Useful to the target user.
- Clear to search engines.
- Fast to load.
- Easy to crawl.
- Easy to share.
- Accessible.
- Structured around real search intent.
- Measurable after launch.

Do not stuff keywords. Do not create generic AI filler. Do not make pages that look polished but fail to explain the product, page purpose, or next action.

---

## Before Building

Clarify or infer safely:

- Primary audience.
- Page goal.
- Main keyword or search topic.
- Secondary keywords.
- Search intent: informational, commercial, transactional, navigational, or local.
- Location target, if relevant.
- Brand or product name.
- Primary conversion action.
- Competitors or reference pages, if provided.

Ask questions if SEO direction affects the product positioning, target market, location, claims, pricing, or regulated content.

---

## Page Structure

Every important public page should include:

- One clear `h1`.
- Logical `h2` and `h3` sections.
- Descriptive intro copy.
- Clear explanation of the offer, product, service, or content.
- Specific benefits.
- Proof, examples, outcomes, or use cases where relevant.
- FAQ section when users are likely to have objections or comparison questions.
- Clear CTA.
- Internal links to related pages.
- Descriptive image alt text.

The first viewport should quickly answer:

- What is this?
- Who is it for?
- Why should the visitor care?
- What can they do next?

---

## Metadata

Add or update:

- Page title.
- Meta description.
- Canonical URL.
- Open Graph title.
- Open Graph description.
- Open Graph image.
- Twitter/X card metadata where supported.
- Favicon and app icons where relevant.

Title guidance:

- Put the primary topic, product, or offer near the front.
- Keep it specific.
- Avoid vague titles like `Home` or `Welcome`.

Description guidance:

- Summarize the page value clearly.
- Include the main topic naturally.
- Avoid fake urgency or exaggerated claims.

---

## Technical SEO

Check:

- The page returns the correct status code.
- Important content is not hidden behind client-only rendering when SSR or static generation is available.
- Robots settings do not block important pages.
- Canonical tags are correct.
- Sitemap includes important public pages.
- Broken links are avoided.
- URLs are readable and stable.
- Redirects are intentional.
- Duplicate pages are canonicalized.
- Images use optimized formats and sizes.
- Layout does not shift unnecessarily.
- Core Web Vitals are considered.

---

## Schema Markup

Use structured data when appropriate:

- Organization.
- Website.
- WebPage.
- Article.
- FAQPage.
- Product.
- Course.
- Event.
- LocalBusiness.
- BreadcrumbList.

Only add schema that matches visible page content. Do not create fake reviews, fake ratings, fake dates, or unsupported claims.

---

## Content Quality

Content should be:

- Specific.
- Human-readable.
- Useful.
- Accurate.
- Original to the product or page.
- Matched to search intent.
- Clear about who the offer is for.
- Clear about eligibility, pricing, timing, location, or requirements when relevant.

Avoid:

- Keyword stuffing.
- Generic AI paragraphs.
- Unsupported claims.
- Duplicate sections.
- Thin pages.
- Hidden text.
- Misleading titles.
- Overpromising results.

---

## Accessibility And SEO

SEO and accessibility should support each other.

Check:

- Semantic HTML is used.
- Headings are in a logical order.
- Links have descriptive labels.
- Images have useful alt text or empty alt text when decorative.
- Buttons and forms are keyboard accessible.
- Color contrast is readable.
- Text is real text, not baked into images.

---

## Local SEO

For local businesses or location-based pages, include:

- Business name.
- Service area.
- Address, if public.
- Contact details.
- Opening hours, if relevant.
- Location-specific copy.
- LocalBusiness schema, if appropriate.
- Embedded map only when useful.
- Clear local CTA.

Do not invent locations, phone numbers, opening hours, licenses, certifications, or reviews.

---

## SEO QA Checklist

Before completion, verify:

- Page title is specific and unique.
- Meta description is useful and unique.
- There is exactly one primary `h1`.
- Headings follow a logical structure.
- Main keyword/topic appears naturally.
- Important content is crawlable.
- Images have useful alt text.
- Links work.
- Page loads quickly.
- Mobile layout works.
- No fake or unsupported SEO claims were added.
- Schema matches visible content.
- Sitemap/robots/canonical behavior is correct where applicable.
